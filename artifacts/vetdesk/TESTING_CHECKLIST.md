# VetDesk testing checklist

Use synthetic staging data only. Never use real animal/client medical information in PayPal, Resend, screenshots, or test logs.

## Automated checks currently available

- [ ] `npm ci`
- [ ] `npm run typecheck`
- [ ] `npm run build`
- [ ] `npm audit --omit=dev`
- [ ] Bundle each `supabase/functions/*/index.ts` entry with esbuild/Deno-compatible externals

Automated Vitest, Playwright, and pgTAP suites are not yet included and must be added before a high-volume production rollout.

## Authentication and staff

- [ ] Signup with email confirmation enabled and disabled
- [ ] First user provisions one clinic and active admin record
- [ ] Pending invited email links to the existing staff record after signup
- [ ] Inactive/pending staff cannot enter the app
- [ ] Receptionist cannot open staff/settings/billing admin screens
- [ ] Last active administrator cannot be demoted/deactivated/deleted

## Tenant-isolation matrix

Create Clinic A and Clinic B with one admin each. Repeat SELECT/INSERT/UPDATE/DELETE attempts using known IDs from the other clinic for:

- [ ] clinics and staff
- [ ] owners and pets
- [ ] visits and visit photos
- [ ] recalls and appointments
- [ ] vaccinations and prescriptions
- [ ] lab orders and clinical documents
- [ ] subscriptions, notification queue, sent emails, and audit log
- [ ] `pet-photos`, `clinic-assets`, and `medical-documents` storage paths

Every cross-clinic read must return no data; every cross-clinic mutation must fail.

## Clinical record

- [ ] Veterinarian creates draft and final SOAP notes
- [ ] Editing clinical content on a final note marks it amended and creates audit history
- [ ] Temperature, heart, respiration, and BCS bounds reject invalid values
- [ ] Receptionist has read-only clinical UI and direct clinical writes fail under RLS/trigger protection
- [ ] Create/apply reusable SOAP template
- [ ] Microchip is unique inside one clinic and can exist independently in another clinic
- [ ] Allergies/warnings are prominently visible
- [ ] Deceased=false rejects retained date/cause values
- [ ] Clinical summary PDF handles multiple pages

## Vaccinations, prescriptions, and laboratory

- [ ] Vaccination with next due date creates exactly one recall
- [ ] Changing next due date updates that recall and reminder queue
- [ ] Product expiry before administration is rejected
- [ ] Prescription end before start and invalid refill counts are rejected
- [ ] Active prescription can be completed/discontinued and is audited
- [ ] Lab order moves ordered → collected → processing → completed
- [ ] Numeric/text result, reference range, abnormal flag, and reviewer are retained
- [ ] Owner-notified timestamp changes only through an authorized clinical user

## Files and privacy

- [ ] Pet images accept JPG/PNG/WEBP up to 5 MB
- [ ] Medical documents accept PDF/JPG/PNG/WEBP up to 10 MB
- [ ] Executables, SVG, HTML, oversized, empty, and spoofed uploads are rejected
- [ ] Buckets remain private where documented
- [ ] Signed URLs expire and cannot be generated by another clinic
- [ ] Internal clinical notes never appear in owner-visible output

## Archive, audit, and recovery

- [ ] Only admin sees archive controls
- [ ] Archive client also hides linked pets without deleting history
- [ ] Physical DELETE on retained records fails
- [ ] Admin recovery RPC restores expected rows
- [ ] Audit log records clinic, user/staff, action, entity, timestamp, and before/after values
- [ ] Non-admin cannot read audit log; normal users cannot mutate it

## Reminders and email

- [ ] Database triggers schedule, cancel, and reschedule appointment/recall jobs
- [ ] Processor rejects missing/wrong `CRON_SECRET`
- [ ] Two processors cannot claim the same queue item
- [ ] Resend idempotency prevents duplicate provider deliveries on retry
- [ ] Failed delivery retries then becomes failed after three attempts
- [ ] Stale processing job is recovered or finalized as failed
- [ ] Test-email admin check and one-minute rate limit work

## PayPal sandbox

- [ ] Expected plan activates clinic subscription
- [ ] Different plan is rejected
- [ ] Subscription cannot be assigned to another clinic
- [ ] Invalid webhook signature is rejected
- [ ] Duplicate webhook is acknowledged without duplicate processing
- [ ] Activated/suspended/cancelled/expired/payment-failed states gate access correctly
- [ ] Use sandbox only; never incur a real charge during QA

## Responsive/PWA/accessibility

- [ ] 360 px, 768 px, 1024 px, and wide desktop layouts
- [ ] No horizontal page overflow; tab strips remain usable
- [ ] Every field has a label and validation/error feedback
- [ ] Keyboard navigation and visible focus through dialogs/tabs/forms
- [ ] PWA install, update prompt/refresh, offline shell, and reconnect
- [ ] No sensitive clinical response is stored in an offline mutation queue

## Regression flow

- [ ] owner → pet → clinical profile → SOAP visit → vaccination → recall
- [ ] prescription → status change
- [ ] lab order → collection → result/review → secure document
- [ ] appointment → reminder → completion → visit
- [ ] refresh after every mutation confirms database persistence
